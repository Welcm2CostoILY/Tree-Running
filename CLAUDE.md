# Tree Running: RuneLite plugin

A RuneLite plugin for daily OSRS Farming tree runs toward a goal, such as 99 Farming. It's live on the Plugin Hub as "Tree Running", by Welcm2CostoILY. See README.md for what users see.

## Build and run

- Java 11+, Gradle. Built against RuneLite `latest.release`, currently 1.13.4, with Lombok.
- `./gradlew build`: compiles and runs the unit tests in `src/test/java/.../core` and `.../data`, plus `RunStateTest`.
- `./gradlew runClient`: starts RuneLite with the plugin loaded in developer mode. Use this, not the test `main`, from IntelliJ.
- `./gradlew panelSnapshot`: renders the side-panel tabs to `build/snapshots/tab-N.png` with sample data, no client needed. Use it to check UI changes visually.
- `./gradlew exportPreviewData`: regenerates data for `preview/tree-running-preview.html`. That file is a clickable JS mock of the panel.

## Layout

- `data/`: static game data.
  - `CropType`: items, XP, growth and payment.
  - `PatchLocation`: 26 tree patches (crystal off by default), each with a varbit, regions, gardener NPC and RuneLite's region exceptions (`isAt`), copied from FarmingWorld.
  - `HerbLocation`: 10 herb patches with their allotments, gardeners, disease-free unlocks and diary bonuses.
  - `HerbType`, `AllotmentType`, `Compost`: herb and allotment data (OSRS Wiki).
  - `PatchStateTable` (generated by `tools/gen_patch_states.py` from RuneLite's PatchImplementation/Produce), read through `PatchKind.read(value)` into a `PatchReading` (`PatchCondition`, stage, crop).
  - `RouteStep`: stops and default travel notes.
  - `PatchType`.
- `core/`: pure logic, no RuneLite API, and unit-tested.
  - `RunPlanner`, `XpProjection`, `XpTable`, `SupplyCalculator`.
  - `Route` and `RouteItem`: the checklist with bank stops.
  - `RouteOrder`: the user's stop and patch order.
  - `RunNeeds`: this run's items against the inventory.
  - `ActionMatcher`: XP drop plus one patch varbit change where the player stands ties the XP to that patch (by key).
  - `HerbPlanner`, `HerbTask`, `HerbSettings`: herb run tasks, steps, needs, yield/profit estimates (Wiki chance-to-save formula).
  - `InventoryFit`: 28-slot check per stretch between bank stops.
  - `SeenPatch`: last seen state of a patch; `RunPlanner.applySeen` uses it for tree due/not due.
  - `PatchMatcher`: sapling-removal fallback.
  - `RunRecord`, `BankStop`.
- Top level:
  - `TreeRunningPlugin`: events, run state and settings persistence.
  - `TreeRunningPanel`: Swing UI with XP, Trees, Herbs and Supplies tabs. Settings are in RuneLite's config panel (sections in `TreeRunningConfig`); only the route editor (bank stops, stop/patch order, travel notes) stays in the XP tab.
  - `TrackedPatch`: every tree/herb/allotment patch with its key, varbit and gardener. Patches are read once per game tick at the player's position (not on VarbitChanged, which can arrive before a teleport moves you).
  - Bank filter: `@PluginDependency(BankTagsPlugin.class)`, `TagManager.registerTag` for two hidden tags, opened with `BankTagsService.openBankTag` on WidgetLoaded(BANKMAIN) via invokeLater and from the "Show worn items" menu.
  - `TreeRunningOverlay`: the checklist overlay.
  - `PatchHighlightOverlay`: patch outlines.
  - `PanelData`: an immutable snapshot that the client thread publishes to Swing and the overlays.
  - `RunState`: per-account state in RS profile config, key `state`, JSON.
  - `DebugLog`: when enabled, logs `[Tree Running]` lines to RuneLite's `client.log`. No file I/O of its own: Plugin Hub flags java.io/java.nio for extra review, and bans process execution such as `LinkBrowser.open`.

## Rules that matter

- A patch is identified by varbit **and** region, because varbits are reused, e.g. 4771.
- Ticking only marks a patch done. Growth timers (`plantedAt`) and run XP are committed in `endRun()` when the user presses Finish run, or by the 12-hour stale auto-finish. Don't set `plantedAt` on tick, or the checkbox can't be unticked. Every ticked patch gets a `plantedAt`, so short crops (calquat 21 h, fruit trees 16 h) aren't shown as due before they can have grown.
- `PatchMatcher` must not fall back to route order when the player's region has a patch of that type that's already done.
- Settings saved as JSON strings in hidden config keys: `bankStops`, `stopOrder`, `patchOrder`, `travelText` (tree stops by `RouteStep` name, herb patches as `HERB_<HerbLocation>`); `bankFilter` is a hidden enum.
- A grown herb or allotment patch steps through three states as it's picked, so a GROWN → GROWN change with XP is a pick. Changes in the first 2 ticks after arriving in an area are the area's varbits catching up, not actions.
- Our own `state` saves fire ConfigChanged; `onConfigChanged` ignores that key.
- Farming XP: the first StatChanged after login only sets the baseline (`lastXp` is -1 until then), and jumps over `MAX_ACTION_XP` are ignored; one XP drop never counts more than `MAX_PICKS_PER_DROP` herbs. `RunState.fillDefaults` drops history entries beyond what any real run reaches (from the old login bug).
- A location's allotments are one `HerbTask` (key `allot:LOC`) covering per-patch keys `allot:LOC:i`; its steps are done when every patch has done them.
- A tree tick needs a real check-health (CHECK_HEALTH → anything else) or a planting (GROWING stage 0); raking (weeds) never ticks.
- Prices come from `itemManager.getItemPriceWithSource(id, true)`, the Wiki live price.
- Owner preference: for UI changes, show a clickable preview (update `preview/`) before changing the plugin.

## Releasing an update

Plugin Hub PR #19586, the first version, is merged. Each update is a **new** PR to runelite/plugin-hub:

1. Push here, then run `git rev-parse HEAD`.
2. In the fork of runelite/plugin-hub, sync with upstream.
3. Edit `plugins/tree-running`:
   - Set `commit=` to the new hash.
   - Set `repository=` too, if this repo's URL changed.
4. Open a PR titled "Update Tree Running".
